Prologue · the whole run

Meet the cast

At 18:20:29 on 27 October 2026, a small app asked Claude to research one topic: renewable energy technologies. 57 seconds later it had a sourced report and the result of an experiment on what a subagent can know. This lesson replays that run from its real log, one message at a time.

Nobody in this story does everything. Each role has one job and only the tools that job needs. Meet them before the curtain goes up.

Appnot a model

The director. A short program that starts each coordinator call, reads the stream of messages that comes back, and runs plain checks that need no model.

Coordinator · the hub

A Claude model that owns three jobs: decompose the topic, delegate the research, and aggregate the reports. It never researches anything itself. Its standing orders open with:

You are the coordinator of a research team: the hub of a hub-and-spoke system. You own three jobs.
Its only tool: Agent which starts a subagent
web-searcher · spoke 1

A subagent that finds sources. The hub reads its one-line job description when it picks a subagent:

Finds Helios Institute sources for a list of subtopics. Use it before doc-analyst.
Its only tool: web_search
doc-analyst · spoke 2

A subagent that reads documents by their exact id. It can't search. Its standing orders end with a rule that matters later:

If your task gives no document id, say which ids you need instead of guessing.
Its only tool: read_document
Agent SDK harness

The stage crew. Inside one coordinator call, it starts each subagent in a fresh context, runs the tools, and hands each subagent's final report back to the hub as the result of its Agent call.

Helios librarymock data

A made-up archive, so Claude has to look things up instead of answering from memory. Seven shelves, one document each:

HX-SOL-7 solar HX-WND-2 wind HX-HYD-5 hydropower HX-GEO-3 geothermal HX-TID-4 tidal HX-BIO-6 biomass HX-FUS-1 fusion

A search returns a headline figure and a document id. Reading the document returns a different figure from inside it.

Ground rules for this run

  1. A subagent starts with a blank memory. It sees its own standing orders, its one tool and the brief the hub writes for it. It never sees the hub's conversation.
  2. Spokes never talk to each other, and they can't start agents. Every message goes through the hub.
  3. The hub waits for each report before it moves on. Subagents run in the foreground, not in the background.
  4. Only these two subagents exist. There is no general-purpose helper to fall back on.
  5. Each coordinator call has a cap on turns and on spending, its subagents included. Each subagent stops after at most 15 turns.

What to take away

    
    
      
  1. The hub decides and the spokes research. Every Agent call came from the coordinator, and every research call came from a spoke.
    2. 
      
  2. Starting a subagent is a tool call. Its whole run comes back as one tool_result carrying the same id.
    3. 
      
  3. A subagent knows only its standing orders, its tools and its brief.
    4. 
      
  4. Context moves between spokes only through the hub, written into the next brief.
    5. 
      
  5. A good brief carries the research goal, the exact subtopic and the context from earlier agents.
    6. 
      
  6. When a subagent's result is poor, check the brief first.
    7. 
      
  7. The decomposition decides the coverage. Check it against what the topic requires.
    8. 
      
  8. Success means the loop ended normally, not that the task worked. Calls that return JSON end with tool_use, and calls that return text end with end_turn.
    9. 
    

  

  

    
The exam lens

    
    
      
  • ✓The coordinator owns decomposition, subagent selection and aggregation. Its system prompt defines it as the hub, and it takes a topic in and returns a structured report.
    • 
      
  • ✓Decompose into at least 5 distinct subtopics that cover the full breadth. For renewable energy technologies that means solar, wind, geothermal, tidal, biomass and fusion at minimum.
    • 
      
  • ✓Use two subagents with explicit context passing. Each brief carries the goal, the full subtopic and the context from prior agents, because subagents share no memory.
    • 
      
  • ✓Aggregate both subagents' results into one structured report, and judge its coverage against the whole topic.
